# Структура файлов для дизайн системы

Это руководство поможет вам понять, какие файлы и папки нужны для создания своей дизайн системы на базе **shadcn/ui** и **Base UI**, а какие можно игнорировать.

### 2. CSS Стили

```
apps/v4/registry/styles/
├── style-nova.css              # Рекомендуемый стиль для начала
├── style-vega.css              # Альтернативный стиль
├── style-maia.css              # Альтернативный стиль
├── style-lyra.css              # Альтернативный стиль
└── style-mira.css              # Альтернативный стиль

apps/v4/styles/
└── globals.css                 # Глобальные стили и CSS переменные
```

**Зачем нужно:** CSS файлы определяют внешний вид всех компонентов - цвета, размеры, границы, анимации.

**Пример содержимого style-nova.css:**

```css
/* Стили для кнопки */
.cn-button {
  @apply focus-visible:border-ring focus-visible:ring-ring/50
         rounded-lg border border-transparent bg-clip-padding
         text-sm font-medium focus-visible:ring-[3px];
}

.cn-button-variant-default {
  @apply bg-primary text-primary-foreground hover:bg-primary/80;
}

.cn-button-size-default {
  @apply h-8 gap-1.5 px-2.5;
}
```

### 4. Утилиты

```
apps/v4/registry/bases/base/lib/
└── utils.ts                    # Функция cn() - критически важна!
```

**Содержимое utils.ts:**

```typescript
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

**Зачем нужно:** Функция `cn()` используется во ВСЕХ компонентах для объединения CSS классов.

## Файлы которые можно игнорировать

### Deprecated код

```
deprecated/
├── cli/                        # Старая версия CLI
└── www/                        # Старый веб-сайт
```

**Причина:** Устаревший код, не нужен для новой дизайн системы.

---

### Radix UI версия (если используете Base UI)

```
apps/v4/registry/bases/radix/
└── ... (53 компонента на Radix UI)
```

**Причина:** Альтернативная реализация на Radix UI. Выберите только одну версию.

---

### New York стиль

```
apps/v4/registry/new-york-v4/
├── ui/                         # 53 компонента
├── blocks/                     # 68 блоков
├── charts/                     # 73 графика
└── examples/                   # 237 примеров
```

**Причина:** Альтернативный дизайн стиль. Можно изучить позже для вдохновения.

---

### App Router страницы (документация сайта)

```
apps/v4/app/
├── (app)/                      # Страницы документации
├── (examples)/                 # Страницы примеров
└── (view)/                     # Страницы просмотра
```

**Причина:** Это документация и демо сайт shadcn, не нужно для вашей дизайн системы.

---

### Скрипты сборки

```
apps/v4/scripts/
├── build-registry.mts
├── build-icons.ts
└── build-examples.ts
```

**Причина:** Скрипты для генерации регистра компонентов shadcn. Вам не нужно их запускать.

---

### Пакеты монорепо

```
packages/
├── shadcn/                     # CLI инструмент
└── tests/                      # Тесты

templates/                      # Шаблоны проектов
```

**Причина:** Это для разработки самого shadcn CLI, не для вашей дизайн системы.

## Рекомендуемая структура для вашей дизайн системы

```
your-design-system/
├── components/
│   ├── ui/                     # Скопировать из registry/bases/base/ui/
│   │   ├── button.tsx
│   │   ├── input.tsx
│   │   └── ...
│   ├── lib/
│   │   └── utils.ts            # Функция cn()
│   ├── hooks/
│   └── internal/
│
├── styles/
│   ├── globals.css             # Глобальные стили
│   └── theme.css               # Один из style-*.css файлов
│
├── config/
│   ├── components.json
│   ├── themes.ts
│   ├── colors.ts
│   └── fonts.ts
│
├── icons/

│
└── examples/                   # Примеры (опционально)
    └── button-demo.tsx
```

## Следующие шаги

1. **Скопируйте базовые файлы** из `registry/bases/base/`
2. **Выберите стиль** из `registry/styles/` (рекомендуется `style-nova.css`)
3. **Настройте конфигурацию** под свой проект
4. **Кастомизируйте компоненты** по необходимости

Подробнее о кастомизации компонентов читайте в разделе [Компоненты](/ru-docs/components).
